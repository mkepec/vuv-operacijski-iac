  **Bugs found and fixed at the source (role/template/design-doc — never worked around in the cheatsheet):**
  - `grade.sh.j2` T3: probe-message check used unprivileged `grep` against a `root:root 0600` log file the student can't read — added `sudo`
  - `grade.sh.j2` T4: manifest content-match check used unprivileged `diff` against a `root:root 0640` file — added `sudo`
  - `repo-provision.yml`: NFS export directories were `mode: 0775 owner=nobody group=nobody` — the `student` client UID (1001) is neither owner nor group, so it landed in "other" with no write bit, and `echo > /remote/<variant>/file` failed with Permission denied for every student. Changed to `0777` (single-tenant exports, scoped per-student by IP, so world-writable is safe and necessary — `no_root_squash` only changes how *root* maps, not how a ordinary non-root client UID is treated under `sec=sys`)
  - `grade.sh.j2` T5: master-map check grepped for the literal full local mount path (e.g. `/remote/alpha`) but indirect-map autofs configs split that across two files — the master map only ever contains the base mountpoint (`/remote`) plus a pointer to the indirect map, which supplies the final path component as its key. Rewrote the check to derive `dirname`/`basename` and verify each file correctly. Also fixed a case-sensitive `grep -qF "welcome"` that didn't match the planted `"Welcome to your NFS export..."` (capital W) — changed to `-qiF`
  - `grade.sh.j2` T2: hardcoded `/dev/sdb` for the dedicated raw disk's PV check — **discovered live, via the end-of-exam reboot, that `/dev/sda`/`/dev/sdb` assignment for the two SCSI-bus disks (OS disk on `scsi0`, raw disk on `scsi2`) is NOT stable across reboots** (confirmed via `dmesg`: kernel assigns `sd*` letters in async-probe completion order, not host/target number — they swapped on this very host after a single reboot). This affects the task itself, not just the grading script — a student could be told "format `/dev/sdb`" and find their dedicated disk is actually `/dev/sda` on exam day. Fixed the **grading check** to identify the disk by elimination (whichever `sd*` disk does NOT back `/`, found via `findmnt`+`lsblk -no PKNAME`) rather than by kernel-assigned letter. *(The task wording itself still says `/dev/sdb` per the design doc — that's a separate, larger question: whether to also change the student-facing instructions to say "the empty `sd*` disk" instead of naming a letter. Left as-is for now since changing student-facing wording has knock-on effects on the task sheet template; flagged here for a future design discussion.)*
  - `grade.sh.j2` T6: all three Podman/systemd checks were wrapped in `sudo -u student ...`, which spawns a session lacking `$XDG_RUNTIME_DIR`/`$DBUS_SESSION_BUS_ADDRESS` — breaks rootless Podman discovery and fails `systemctl --user` outright ("Failed to connect to user scope bus"). `grade` already runs as the `student` user (root:root 0755, self-run) — the wrapper was both unnecessary and actively harmful. Removed it from all three checks

Fixed by redeploying via `-e @vars.yml` (a proper YAML file) instead of inline `-e` strings — this is the safer pattern for any future targeted redeploys with multi-word values
  - **Design-doc inconsistency** (`exam-rh134-design.md` §Task 3): the "Ansible provisioning needed" note said "ensure rsyslog is in its default running/enabled state — no special setup needed," directly contradicting Task 1's own deliberate "mixed active/enabled states" baseline (which sets `rsyslog` to inactive+disabled on purpose, so T1's report shows varied states).
